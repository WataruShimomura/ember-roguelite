# Codexへの依頼：EMBER Ver.0.2

## ミッション
既存のGodot 4.6 / GDScript製 Ver.0.1 を土台に、**戦闘→報酬→次戦→イベント→最奥ボス→冒険リザルト**が1周遊べる短いローグライトプロトタイプを実装する。UIと素材は仮でよい。目的はゲームデザインの検証であり完成版ではない。

本ファイル、`V02_GAME_SPEC.md`、`ARCHITECTURE_AND_TESTS.md` の3資料を熟読し、ルートの `AGENTS.md` も遵守。競合した場合は本版の仕様を優先。

## 作業ルール
- 既存 `main` と Ver.0.1 の比較可能性を維持する。コード変更は `main` 派生の `feature/v0.2-roguelite-loop` など別ブランチで行い、`instructions/v0.2` は書き換えない。
- 作業前に現在のクラス・依存関係・テストを読み、変更計画を短く記録する。
- UIにゲームルールを書かない。データ定義、RunState、BattleState、計算、効果適用、画面を明確に分離する。
- 戦闘の予測と実行は同じ計算ロジックを使用し、UIには計算根拠を表示する。状態・乱数をプレビューで変えない。
- 実装が難しい場合、機能を暗黙に省略せず、未実装項目と理由を報告する。勝手に恒久強化や大規模なマップ・ストーリーを足さない。

## 実装順
1. 既存戦闘テストが通る状態を確認して基準点を残す。
2. 共有TPからキャラ個別TPへ変更。MAX_TPとCURRENT_TPを分離し、共通防御コマンドを削除。個別のTPコストを計算・プレビュー・ログ・UIに反映する。
3. RunState/RunManagerを作り、戦闘間HP/TP/装備/消費アイテムを持ち越す。状態初期化の境界を明確にする。
4. 4戦の短いルート、勝敗分岐、報酬3択、イベント2択、装備の獲得・交換と消費アイテムを接続する。シードで報酬と編成を再現可能にする。
5. 与えた**新規削減HP**に比例したHP/TP吸収を導入。敵回復後の再削減を利用した無限吸収を防ぐ。
6. 防御/反撃、吸収、瞬間火力など異なるビルド方向性を少数の装備で用意する。共通防御コマンドは復活させない。
7. 戦闘別ログ・冒険全体のHP/TP推移・報酬履歴・シードをリザルトで確認できるようにする。
8. 自動テストと描画ありスモークテスト。操作性の手動確認方法を用意して設計報告を残す。

## 受入条件
- 起動からクリアまたは全滅まで、仮素材で途切れずプレイできる。
- 少なくとも通常戦2、強敵戦1、ボス戦1、および間の報酬・イベントがある。
- TPは個別、HP/TPは持ち越し、戦闘単位のバフ/状態異常はリセット。
- 共通防御と通常攻撃の無条件TP獲得がない。
- HP/TP吸収は実ダメージかつ新規削減HPの範囲でのみ発生。無限回復ループのテストを含む。
- ステータス、スキル、報酬、装備、敵編成がデータで調整できる。
- 入力の二重適用がなく、計算プレビューと実行が一致し、同じシード・同じ選択列が再現される。
- 既存テストは変更されたルールに合わせて更新し、修正理由と実行結果を記録。

## 最終報告
- 変更ファイル、主要クラスの責務、仕様との差分、暫定数値とその根拠。
- 自動テスト数、実行したコマンド、失敗・未検証事項。
- 少なくとも2種類のビルドで通しプレイした結果（HP/TP・ラウンド数・行動傾向）。
- UI操作の手順、画面キャプチャ（可能なら）、次に検証すべき仮説。
- PRの本文に本指示のGitコミットSHAを記載。
