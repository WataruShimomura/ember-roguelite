# Codexへの依頼：Combat Core v1を実装し検証する

## 目的
EMBERの**戦闘1回の基礎**を、人間が定めた具体的なスキル・TP・装備・敵の役割で作り直し、Godotで遊べる状態にする。自由に別ゲームを設計する仕事ではない。完成までの既存コードの活用は自由だが、楽しい選択を満たすことを優先する。

## 作業条件
- 指示: `instructions/combat-core-v1/` のREADME/COMBAT_SPEC/**PROGRESSION_AND_DIFFICULTY**/TEST_AND_ITERATION/本ファイル
- コード: `feature/combat-core-v1` ブランチへ。基点は `feature/v0.3-growth-tp` の `c21c5bc4d42ff83602d2f74bd4d5f18c1678eed5`。
- 指示ブランチは変更禁止。main、Ver.0.2/0.3、Design Labの他ブランチを無断変更・マージしない。

## 仕事
1. 旧コードと既存テストを把握してベースラインを記録。
2. 独立した `combat_core_v1/` ディレクトリに戦闘シーン・ルール・データ・テスト用ハーネスを実装。さらに**通常戦→強敵戦→ボス**の成長付き短期テストルートを実装する。元の4戦周回とは分離。
3. スキル18候補、各キャラ6から4持込、通常攻撃、敵3種類、2編成、装備で戦法が変わる3ビルドを実装。確率や状態で曖昧な効果は具体値に落として `docs/combat-core-v1/DECISIONS.md` で根拠を記載。
4. TP上限30、開始18、無条件自然回復なし、敵のHP閾値による有限TP獲得（対照の回復なしも切替）を実装。戦闘中治療は残す。遅延悪用の例外を検査。
5. F1〜F6の局面を保存・復元できるテストモードを作り、固定シード・複数方針でスキルと装備の比較。**戦後の数値成長とスキル・装備選択を最低2回実施し、U0（無成長）/U1（数値のみ）/U2（戦術のみ）/U3（両方）を同じ敵・同じシードでボスまで比較する。初期構成のまま簡単にボスを倒せる場合は未達として難度を再設計。**
6. 実描画でUI・操作・予告の整合をチェック。Godot MCPが利用できない場合は代替手段を使い、未実施を明記。
7. 結果を記録して**自律的な小規模調整を2回まで**行ってよい。**数値/戦術成長と敵の対処要求を成立させる初期実装・初期難度校正はこの2回に含めず、必須仕様の一部として先に完了する。**各回、仮説・差分・数値・副作用・反例をコミット単位で記録。試作の全面再設計は報告・承認待ち。
8. `docs/combat-core-v1/` に `IMPLEMENTATION_REPORT.md`、`TEST_REPORT.md`、`DECISIONS.md`、`ISSUES_AND_PROPOSALS.md`、**`PROGRESSION_REPORT.md`**、比較用JSON、可能なら画面キャプチャを記録。Godotの起動手順と人間用プレイ観点を明記。
9. `feature/v0.3-growth-tp` 宛てに**試作のみ・未採用**と明記したレビュー用PRを作成する。既存PRのマージ不要。

## 禁止事項
- 初期装備・初期ステータスでボスまで難なく勝てる状態を完了扱いしない。
- 成長を空き装備枠や技の名前変更だけに留めない。数値面の強化も戦法の拡張も必要。
- U0を弱いAI、U3を強いAIで測って成長による改善と誤認しない。
- HP・攻撃力を単純に激増させるだけのボスで、装備・スキル選択の価値を偽装しない。
- 成功のために現行の旧テストを削除しない。
- 無限回復防止のため戦闘中治療を削るだけで済ませない。
- 合法コマンドを大量に作るだけで、選択肢が豊富と結論しない。
- ビルド差を同じスキルの数値上昇だけで説明しない。
- 敵が簡単になって勝率が上がっただけで面白さが改善したと主張しない。
- 実行していないMCP操作や人間の手触り検証を実行済みと主張しない。
