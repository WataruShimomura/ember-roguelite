# Combat Core v1：テスト、反例、改善権限

## 手順
1. 既存Ver.0.3を回帰テストし、ベースSHA記録。独立シーン/ロジックに新試作を作成し、旧UI/4戦のプレイを壊さない。
2. `COMBAT_SPEC.md` の役割・18技・3敵の仮実装をデータ駆動で揃える。3ビルドと2編成を起動できるようにする。
3. 実行前に技ごとの「選びたい局面／選びたくない局面」を表にして、通常攻撃との支配関係を検査する。実戦結果に応じ数値と細部を再調整。
4. TP回復なし／有限HP閾値ボーナスを同一状態で比較。強い敵を狙うしかない構造や、敵のHPを寸止めする最適戦術が出たら明記。
5. 速攻・回復/継戦・防御/反撃・状態異常/連携・温存・遅延悪用・合法ランダムの方針で比較。数値だけでなくコマンド列・対象・予告・装備発動も記録。
6. Godotで画面操作/表示確認。MCPが利用可能なら使う。使えない場合は描画付きGodotスクリプト操作＋キャプチャ。人手の感覚を代弁したことにしない。

## 成長と難度の追加検証（最優先の合否項目）
- [PROGRESSION_AND_DIFFICULTY.md](PROGRESSION_AND_DIFFICULTY.md) のU0/U1/U2/U3を同条件で比較する。初期ステータス/初期装備で終盤ボスまで簡単に勝てるなら、試作の評価はFAIL。
- 通常戦→強敵戦→ボスの独立した成長付きテストルートを実際に操作し、戦後のレベル/能力値上昇と、スキル・装備/構成の選択を確認する。
- 攻撃連携/防御反撃/継戦型の3経路について、成長によって合理的なスキル・対象が変わることをログで示す。
- `docs/combat-core-v1/PROGRESSION_REPORT.md` を必須成果物に加える。

## 固定シナリオ
- F1: 魔術師が次敵手で致死予告、盾兵が詠唱士を守る。最初のTP18、各自TP4、各自TP0で試し、撃破/中断/移管/減衰の違いを見る。
- F2: 盾兵が防御し、詠唱士は非詠唱。防御解除と別敵先殺しの選択を比較。
- F3: 魔術師が敵へ「火傷」「標的」の一方を付与し、剣士の連携撃／魔術師の爆ぜ火／通常攻撃を比較。
- F4: 残敵HP5、次の戦闘へTP・HP引継ぎを想定。即撃破と2〜4ラウンド残して回復/TP獲得を比べる。
- F5: ボス相当HP2〜3倍、開始TP4/18/30、TP供給あり/なしで枯渇・通常攻撃率・ターン数を比較。
- F6: 同じ戦闘開始状態で装備なし、攻撃連携、防御反撃の3ビルドを比較し、使用技・対象・発生源・最終HP/TPを記録。

## 評価指標
- コマンドの支配関係: 各技に少なくとも1つの合理的な選択理由と1つの不利局面があるか。実際の候補から外される技を「多様性」と数えない。
- 回復・資源の悪用: 瀕死敵放置、敵回復、火傷DoT、反撃、対象変更、KO後、オーバーキルからの二重配布がないこと。
- 戦闘の判断: 致死予告に少なくとも2つの別解、複数の敵配置により攻撃優先度が変わる、装備前後で次に選ぶコマンドが変わる。
- TP収支: 満タン手番、ゼロ手番、無効なTP配布、技の使用数/コスト・行動率。数値の良し悪しのみで結論づけない。
- 手触り: スキルを4つ持込んだUI、装備の説明、敵予告と次手がプレイヤーに理解可能か。人手プレイ前には未確定と明記。

## Codexの裁量
**自律的に変えてよい**: ダメージ、HP、TPコスト、有限TP配布量と閾値、技の発動条件や持続、敵の行動頻度、装備の閾値、画面の配置、操作性。理由と変更前後ログを残す。
**変更前に提案する**: TP自体の廃止、個別→共有への転換、行動方式、スキル持込枠、キャラ数、通常攻撃/回復技の完全削除、固定の敵予告原則、戦闘間引継ぎ。これらがボトルネックなら隠さず問題と代替案を明記し、承認まで現行案を比較保存。

## 受入
- **パーティが数値面・戦術面で強くなり、初期構成でボスが容易に攻略できないこと。** U0/U1/U2/U3の比較とボスの明確な対処要求を証拠付きで提出する。
- 新試作が操作でき、少なくとも3ビルドが同じ2編成をプレイ可能。6候補/4枠のスキル選択が機能する。
- TP30の数値とスキルコストが一貫。有限回復イベントは二重発生しない。
- 2つの敵予告に対して、意義の異なる2つ以上の行動が成功例で示せる。
- 回復で資源を無限稼ぎする反例があればテスト失敗としてレポートし、黙って承認扱いにしない。
- 予測と実行の整合、実操作テスト、旧ゲーム回帰。
- 自動テストが全部通っても楽しさは未確定。評価表に `PASS / RISK / FAIL / UNKNOWN` を付け、未解決を明示する。
