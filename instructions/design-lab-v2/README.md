# EMBER Design Lab v2：戦闘システム再設計

## ミッション
既存Ver.0.3を小さく調整するのではなく、プレイヤーが体験する意思決定から**戦闘システムを複数案設計し直す**。構造が合理的なら既存コードを破棄してよい。既存コードを再利用しやすいことは、設計案を採否する基準にしない。

## 対象とブランチ
- 現行比較用: `feature/v0.3-growth-tp`、コミット `c21c5bc4d42ff83602d2f74bd4d5f18c1678eed5`
- 旧実験結果: `experiment/design-lab-v1`、実験レポート `docs/design-experiments/`
- この指示: `instructions/design-lab-v2`
- 設計成果物: `design/design-lab-v2`（現行Ver.0.3と同じコミットから作成済み）
- 2026-11-18現在、`main` はVer.0.1。基準にしない。既存PRと実験ブランチは無断変更・マージしない。

## 読み順
1. `DESIGN_BRIEF.md`: 目標体験と現行の問題
2. `CODEX_TASK.md`: 実施手順・段階的な成果物
3. `EVALUATION_PROTOCOL.md`: 設計案の批判・検証・採否基準
4. 現行コード・`AGENTS.md`・`docs/v0.3/`・`docs/design-experiments/`

## 今回のフェーズ
**Phase A: 設計案の発散・比較が必須。** Codexは3つ以上の**構造的に異なる**戦闘方式を提案し、スキル・TP・行動順・敵予告・装備/成長を具体化する。単なる倍率やコスト違いの3案は不可。

**Phase B: 有望な2案の最小戦闘試作を許可。** 第一段階の分析と比較文書を完成させてから実装。複数案の違いを確認できる独立ハーネスやシーンにし、既存Ver.0.3の機能一式に統合しない。準備に支障があれば具体的な設計・テスト計画を優先して部分完了を報告。

**Phase C: 人間レビュー待ち。** 正式採用・本編統合・既存PRのマージはしない。比較データと画面・コマンドで、後から人間が案を試せるようにする。

## 指示の哲学
「現状に似ている」「差分が少ない」「既存テストを通せる」は採用理由にしない。代わりに、プレイヤーの選択がどう面白くなるか、最適戦術の退屈さをどう排除するか、新たな負担が何かを説明する。
