# Combat Core v2：比較、反証、合格の考え方

## 1. ベースライン
`feature/combat-core-v1` のコミット `49c9f13a697a07b6d2e96c80ad566f389d8731bd` と、`docs/combat-core-v1/` を参照。
v1での代表値：U0 0/60、U1 17/60、U2 0/180、U3 139/180。U3のビルド別では攻撃53/60、防御56/60、継戦30/60。閾値TPなし対照は全敗、TPなしでの通常攻撃率が93%。これらは**旧ルールでの比較値**であり新設計で同一値を強制しない。評価時は新ルールの同条件比較と区別。

## 2. 実装・調整を2段階に
**Stage 1（情報とルール）**: UIと汎用状態、別キャラ連携、回復アイテム、個別報酬と成長を実装。F1〜F6に対応した新固定局面で、表示/操作と予測一致、装備前後の差を確認。旧版比較を保存。
**Stage 2（難易度と選択）**: 3戦を通してU0/U1/U2/U3と複数ビルドを同条件で検証し、ボス/TP/報酬/敵の行動を校正。初期で楽勝に戻らないことを確認。数値のみの成長が他を圧倒しないよう、個別報酬の意味を示す。

## 3. 固定の反証ケース
- T1 汎用性: 破甲に相当する技が盾兵だけでなく高防御の別敵で意味を持つ。敵専用条件分岐はない。非防御の敵では通常攻撃等が勝る局面がある。
- T2 状態と連携: 魔術師が火傷付与→剣士が火傷を利用、衛士が火傷付与/維持→魔術師が火傷消費、をそれぞれ成立させる。付与者が違っても計算が一致。持続/消費/失効を明示。
- T3 維持vs消費: 同じ敵に火傷を維持する方が残HP/持越資源で得なケースと、直ちに消費して撃破する方が得なケースを1つずつ示す。
- T4 回復有限性: 即撃破して戦間に回復アイテムを使う場合と、敵をHP5で残し3周期待つ場合を比較し、遅延だけでHP/TP/アイテムが増えないこと。敵自己回復と閾値再獲得も検査。
- T5 個別報酬: 初戦後にアイテムX、装備Y、スキルZを比較し、それぞれ次戦の操作/対象/残HPに異なる利点と機会費用がある。2回の獲得を順不同に行い、どちらかが一式プリセットに強制されない。
- T6 ボス非専用鍵: 直接火傷を使わない攻撃/防御/予告調整のいずれかでボスを突破できる、あるいは倒せなくても成功に近づく有効な経路を示す。特殊技必須フラグがないことを静的検査。火傷ルート自体は有利でよい。
- T7 UI判読: 戦闘、結果、レベル、報酬、持込変更、状態詳細の各表示で何を得たか/失ったかを示す。キーボード/マウスで詳細に到達でき、1280×720と1600×900で文字欠け/オーバーラップがない。
- T8 成長差: U0とU3のボス突破率に明確な差、U1/U2の実力、3つ以上の報酬組合せで初手/対象/手順が変わる。未育成で簡単に最後まで勝てるならFAIL。
- T9 資源失衡: 閾値TPあり/なしの比較と、長めの敵HP・低TP局面でスキルが消えて通常攻撃だけにならないか、特定の範囲技で閾値回収が過大にならないか。
- T10 理解可能な説明: UI内に「火傷2」「消費して予測+N」「今回の効果不発理由」「次にレベル上昇/報酬選択」を日本語で説明でき、実際の効果と一致。

## 4. 自動比較ポリシー
同じシード・敵・初期状態・攻略方針の対を使う。速攻/防御/状態利用/TP温存/有限回復/遅延/合法ランダム/状況判断を比較。少なくとも各成長群と、代表的な個別報酬経路の比較を含む。AIは1手先評価に偏りうるので、2〜3手の連携をするポリシーか固定スクリプトの再現ケースを補う。
- 勝率、ボス到達率、残HP/TP、使用技、技の支配関係、状態付与者/消費者、報酬獲得順、装備効果発動、回復アイテムの獲得・消費を記録。
- 単純に旧v1の勝率と新v2の勝率を比較して「強くなった」としない。ルールが違うため。新v2内でU0/U1/U2/U3を比較。
- U3目標50〜80%、U0目標20%以下は**初期の校正目安**。敵HPを一律何倍にもするだけ、弱いAIをU0だけに使う、ボス専用状態鍵で勝率をつくることは禁じる。
- 検証できなかった条件はUNKNOWN、失敗した条件はFAILで残す。「クリアしたこと」と「面白いこと」を混同しない。

## 5. 成果物
`docs/combat-core-v2/`:
- `DESIGN_CHANGES.md`: v1→v2の技・敵ギミック・状態・回復・成長変更対照表と採用理由
- `UX_REPORT.md`: UI導線、詳細表示の実例、解像度別スクショ、認知上の未確認点
- `COMBAT_REPORT.md`: 連携実例、有限回復、2〜3手の分岐、ビルド/装備で変わる行動、敵汎用ルール検証
- `PROGRESSION_REPORT.md`: U0〜U3/3戦/複数ビルド/報酬の比較、難易度とTP収支
- `TEST_REPORT.md`: Godot実行、描画UI、旧回帰、再現コマンド、PASS/RISK/FAIL/UNKNOWN
- `OPEN_ISSUES.md`: 強すぎる技、死に技、UI課題、未解決の設計問題、ユーザーテスト観点
- 機械集計JSONと主要なUIスクリーンショット。

## 6. 受入
v2はすべてを完璧にする必要はないが、**T2/T4/T5/T7/T8は必須のゲート**。満たせない場合「実装完了、設計未達」と正直に報告し、欠落点を次段階でレビューできるようにする。正式採用は人間の判断待ち。
