# Combat Core v2：ゲームデザイン具体仕様

## 1. 非交渉の体験目標
- 通常・強敵・ボスで同じ技が毎回同じ意味を持つのではなく、敵の人数・行動・残HP・状態・味方の持込/装備で選択理由が変わる。
- 3人それぞれが別キャラの付与した状態に関与できる。例えば火傷の付与、維持、消費、拡散、火傷を参照した別行動など。3人が完全に同じ効果を使う必要はない。
- 「このボスにだけ効く解除技」をつくらない。**一般化されたゲーム内ルールの相互作用**の結果、さまざまな攻略が成立する。
- HP回復は有限なアイテム中心。使うタイミングに機会費用があり、3戦を通して適度に入手可能。ただし毎戦満タンに戻せるほど確定供給しない。
- 戦術報酬はプリセットされた完成ビルドへの丸ごと切替ではなく、**個々の装備、技、パッシブの選択・獲得・交換**。1つずつ構成が変わる様子を表示し、成長2機会の各段階で実際の使い方が変わる。

## 2. 既存から維持する要素
- 味方剣士/魔術師/衛士3人。戦闘前の6候補から4スキルを持込（通常攻撃は別）。基本個別手番、次行動順表示、敵の予告・対象・概算被害公開、HP/TP持越し、3戦ルート、数値Lv成長。
- v1のTP30・開始18と敵HP閾値からの有限TP供給は**初期対照**として保存。問題があれば代替供給方式を提案/並走比較し、無断で時間経過による無限供給を戻さない。既存F1〜F6とU0〜U3比較は残す。
- ボスは単なるHP/攻撃力の塊にしない。成長や戦術を要するが、全構成が特定状態異常を持たなければ突破できない仕様にはしない。

## 3. 状態異常とスキルの抽象ルール
- 最初は**火傷＋防御/体勢の変化＋「標的」など1つの連携状態**の合計2〜3系列程度を深掘りする。状態を多数追加して複雑さで代用しない。
- 火傷は共通データ（付与者、強さ/残り回数、発動時刻、重ね掛けと上書き、減少と消費、敵撃破時の処理）で管理し、複数キャラのスキルと装備が同じルールを参照する。特定キャラ以外が付与/消費しても破綻しない。
- 最低限の具体例:
  1. 魔術師の炎弾が火傷を付与し、爆ぜ火で残り回数を消費して即時ダメージに変える。
  2. 剣士の新規または改修した1技は「火傷中の敵へ使用すると追加効果」もしくは「火傷を消費し別の強み」を持つ。火傷がない場合にも最低限の一般用途がある。
  3. 衛士の反撃、庇護、または別の技・装備で火傷の付与/維持/他味方への連携のいずれかができる。元の防御役割を犠牲にしない。
  4. 装備は「爆ぜ火だけの強化」より広い発動範囲を重視。例：火傷を消費したとき（実行者を問わず）追加の状態/TP/他敵への伝播、反撃成功で次の味方の状態効果を強化、など。
- **同じ敵へ火傷を維持する手と消費する手を比較**。残りの敵行動・必要な撃破点・TP・味方の行動予定により最善が変わること。火傷中にあらゆる技が単純に増強されるだけの上位互換は禁止。
- 新設した汎用効果は少なくとも盾/詠唱/治癒兵/ボスの2種以上で用途と代償を示す。敵専用IDやボス専用IDの分岐は原則追加しない。

## 4. ピンポイントメタの見直し
- v1の「儀式防護43%」「火傷＋標的/爆ぜ火/反撃だけで解除」「再詠唱だけ中断無効」「盾の護衛だけを解除するための破甲」などをレビューする。
- 防護の対策は**一般的なルール**へ置き換える。例：固定の防御値・防御姿勢（一定条件で弱まる）、防御貫通、属性/継続、敵行動への介入、狙う順番、火傷の持続/消費、持久戦。どれも一部状況で有利であり絶対の正解ではない。
- 特殊ボス技は存在してよいが、特定スキルを持っていないと破れないロック＆キーにはしない。解除方法が1個増えただけで汎用化と主張しない。**効果側を抽象化**すること。
- 防御や庇うに関しても、特定の1技だけが解除法にならない。別対象への攻撃、範囲、持続、軽減貫通、護衛役の先殺しなど各手段に代償と使い所を設ける。
- 18スキルは維持候補だが、効果を全面再整理してよい。変更前後の対照表を作り、死に技や用途の薄い技の統合・変更は認める。単純な高打点技も、撃破タイミングという明確な役目があれば残してよい。

## 5. 回復とHP資源
- **応急/魔力転換など単純なHP回復スキルは、初期の持込から外してよい**。削除・汎用支援への再設計も許可。ただし有限回復、戦闘中の緊急回復、軽減主体の継戦ビルドの差を比較し、結論を記録する。
- 回復の主供給を有限アイテムへ。**初期1個、戦闘後の選択報酬や特定イベントで獲得**などを検証用仮ルールとして設定。戦闘中使用の可否・1手消費・回復量・所持上限・HP満タン時の扱いを定義。戦闘間使用可。
- 3戦ルートで最低1回は回復アイテムを獲得する機会を提示する。ただし確定で無料満タン回復する構造にしない。回復とスキル/装備報酬の選択でトレードオフを作る。
- 回復アイテムを貯めて使う判断、ボス前に使い切る判断の双方に意味を持たせる。瀕死敵を残しても回復量・所持・TPが増えず、即時撃破後に同じアイテムを使えること。
- 回復役は予告を弱める、庇護、状態異常解除、バフ、TP支援などで独自の役割を継続する。単純な回復技を削ったから支援役がただの攻撃役にならないこと。

## 6. 報酬と成長を選択式へ
- v1 `route.gd` の `moves = Catalog.data.builds[path]` による**完成形への全置換は廃止**。数値Lv成長は継続してよい。
- 報酬は「スキル解放」「個別装備」「有限回復アイテム」等の小さな選択肢から得る。各キャラの候補6技/持込4は維持し、獲得/解放した技だけを出撃準備画面で使用可能にする（初期から一部候補解放済み。ビルド完成に必要な技が後から追加）。
- 装備は人物ごとに1枠、複数報酬で段階的に取得。保有物・装備物・持込4枠を分け、戦間に交換可能。取得と自動装備を混同しない。
- 初戦後と強敵戦後、最低2回の選択を実装。両方で数値Lvの上昇を明示し、さらに報酬を選ぶ。選択肢の表示は候補3個を基本とし、各選択の比較・適用結果を確認可能にする。
- 攻撃・防御・継戦の3方向へ発展可能だが、あらかじめ決めた一式へ瞬時に変身させるのではない。途中で混合ビルドへ方向転換できること。
- ローグライトの本格的なランダム報酬経済は対象外。今回の小さな報酬プールは内容を指定可能な固定シードで構わないが、2つの異なる報酬選択経路がボスで使える状態を作る。

## 7. 難易度の継承と評価
- 「無成長U0でボス楽勝」を再発させない。U0/U1/U2/U3を同じ敵・シード・攻略方針で継続比較する。
- **旧v1の勝率をそのまま再現する必要はない。** 比較対象のルールが変わるため。代わりに、U0の無成長とU3の育成後に有意な実力差があり、U3でも戦術的に誤った技・装備なら負ける状況を維持する。
- U2（戦術だけ）が弱すぎる/ゼロ勝に固定される問題を改善する余地を検討。ただしU2がU3を常に上回る必要はない。数値Lvだけで簡単にクリアできる場合も失敗候補。
- ボスの強みは数値、防御/構え、複数予告、味方を守る敵、持続/状態、行動タイミングの**組合せ**に置く。ボス専用解除技を必須にしない。初期装備でも強いプレイなら稀に勝てる余地は残す。
