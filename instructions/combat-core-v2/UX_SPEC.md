# Combat Core v2：テストプレイ可能なUIの最低要件

**UIは必須機能**。ドット絵・アニメーション・美観の完成度は問わない。しかしスキルや成長の情報不足でプレイヤーが選択できない場合、ゲームデザインの評価そのものが無効になる。

## 1. 情報階層
常時表示（最低限）：味方3人のHP/TP、現手番/次手番、敵のHP/状態と次行動予告、選択可能な技/消費TP、対象、現在の所持・使用可能な回復アイテム。
選択時表示：技の正確な効果、対象制限、条件付き追加効果、解除/付与する状態、行動後のHP/TP差、装備の相互作用、予告がどう変化するか。
詳細表示：用語（火傷、標的、防御/庇護など）の説明、持続時間と発動時点、効果重複ルール、ダメージ計算の主要な内訳、発動しない理由。
同じテキストだけを大量に列挙せず、見出し/グループ/色やアイコン/ツールチップ・詳細欄を分ける。

## 2. スキル一覧・説明
- 技一覧に名前・消費TP・一行説明・使用可否を常時表示。無効なら理由（未習得・持込外・TP不足・対象なし・発動条件なし）を示す。
- 技をフォーカス/ホバー/選択で詳細説明を開ける。マウスとキーボードの両方で同等に情報を取得できる。ツールチップだけに依存しない**固定の詳細パネル**を推奨。
- 「敵に追加ダメージ」だけでなく「火傷を消費、追加18、消費後の残り火傷0」のように**具体的な数値・前後の状態**を示す。条件不成立時も基本効果を表示。
- 実行確定前に予測対象、HP変化、TP消費・獲得、敵の次の攻撃被害、複数対象なら全対象の結果を確認できる。複雑な将来展開の保証ではなく、その時点の規則に沿った正確なプレビュー。
- 装備発動時は理由と効果を明記。「装備効果あり」だけでは不十分。予測/実行ログ双方で具体的に何が起きたか表示する。

## 3. 戦闘結果と成長の画面分離
- **戦闘結果**：「第n戦 勝利/敗北」、被害と残HP/TP、獲得した回復品などが分かる。次のボタンが「報酬選択へ」「冒険結果へ」と明確。
- **レベルアップ**：Lv2→Lv3など、キャラ別のHP/基礎威力等の before/after、現在HP加算の有無を示す。自動成長なら「数値成長は自動」と明記。
- **報酬選択**：「次の報酬を1つ選ぶ」、選択肢が装備/新スキル/回復品のどれか、獲得後の用途、所持数、現在装備・競合枠、選ばなかったものが失われることを表示。
- **スキル構成変更**：持込4枠の現在→変更後、習得/未習得、競合/外す技とその理由、装備との連携を表示。スキル獲得と即時持込を区別。
- 同一画面に結果/レベル/報酬/装備を全部混在させない。ウィザード式でもよいが各画面に**現在の段階と次に何が起こるか**を表示し、前後の比較を必須とする。

## 4. 誤操作とアクセシビリティ
- 選択状態と確定ボタンを視覚的に区別。使用できない技をグレーアウトして理由を示す。報酬は確定前に選択内容確認。
- 重要な情報を色だけで伝えない。数字と語で補足。日本語、極端に小さな文字/切れ/重なりを避ける。キーボード操作のフォーカス移動を確認。
- コマンド数が増えたため、画面高さ・スクロール・ツールチップの画面外はみ出しを実描画で検査。最低でもウィンドウ1280×720と1600×900で検証。
- 予測と実際の確定処理は同じ効果計算を利用。ホバーやプレビューでゲーム状態/報酬所有状態を変更しない。
- 画面ごとに操作導線が分かる案内を短く添え、長い説明書を読まないと操作できないUIにしない。

## 5. UI受入タスク（Godot実操作）
1. 初見相当のプレイヤーが戦闘準備画面で6候補と4持込枠、装備の所持/装着を区別できる。
2. 敵の大技予告を見た状態で、スキル一覧→詳細→対象選択→予測→実行の順に迷わず操作できる。
3. 火傷の付与→別キャラの利用→消費が何を変えたか詳細パネルとログで確認できる。
4. 戦闘勝利後に結果→レベルアップ→報酬選択→装備/構成変更→次戦へ、という段階がそれぞれ判別できる。
5. 回復アイテムの個数、戦闘内/戦闘間使用方法、使った場合のHP変化が分かる。
6. 不足TP、対象なし、未習得技、装備枠競合、報酬二重選択などの理由が伝わる。

重要な画面についてスクリーンショットを残す。自動クリック確認だけでは「分かりやすさ」を証明できないので、未確認点は人間レビューに残す。
