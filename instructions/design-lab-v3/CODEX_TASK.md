# Codex向け依頼：Design Lab v3 / 設計審査のみ

## やること
1. Ver.0.3とDesign Lab v1/v2の資料を読み、以前の失敗と、なぜ修正が保守的になったかを検討する。
2. 戦闘でプレイヤーが考える「敵の意図 → 自分の選択 → 次戦への影響 → ビルドの進化」を体験目標として具体化。
3. **異なる設計思想の案を3つ**提示。単に一括/時系列/固定手番の進行方式が異なるだけでは不可。資源経済・スキルの選択肢・報酬/成長の3課題を**各案内で一貫して解く**。うち1案は、TPそのものの廃止や別資源の採用を真剣に検討してよい。
4. 各案に、基本戦闘コマンドとキャラ別の候補数/持込枠、資源の仮数値、敵予告と行動順、報酬選択、成長後のビルドを具体化。
5. `SCENARIOS_AND_ACCEPTANCE.md` のS1〜S6を**各案に適用**。S1/S3/S4/S5は計算可能な具体例を最低1つ、残りも明確な比較を示す。各結果はPASS/RISK/FAIL/UNKNOWNに分類し、反例を探す。
6. 最小3案を厳しく相互比較し、有望1〜2案と見送り案を選定。既存コード再利用・変更行数・既存テスト通過数を主要な採用根拠にしない。
7. 人間のレビューで判断する論点を最小限にまとめ、**採用未決の戦闘案1〜2件についての次段階試作仕様**を別途作成する。仕様は戦闘の核・初期状態・必要なUI・測定・合否・起動方法を記す。まだ実装しない。
8. `docs/design-lab-v3/` に成果物を保存。作業ブランチ `design/design-lab-v3` を使用し、`design/design-lab-v2` ベースのPRを作成する。指示ブランチを変更しない。

## 今回の明確な禁止事項
- ゲーム戦闘のGDScriptや既存シーン・データを更新しない。
- 設計比較より先にGodotの新たな戦闘プロトタイプを作らない。
- 3案を「既存システム＋細かな数値差」にしない。
- 3案を単に戦闘順序だけ変えた同じスキル・報酬体系にしない。
- TP最大5や各キャラ2スキルを前提にしない。
- S1〜S6の失敗ケースを都合よく成功判定しない。
- 「複雑なので戦略的」「使用率が上がったので面白い」を証明扱いにしない。
- 旧PRをマージしない、mainやVer.0.3のコードを変更しない。
- 大量に新要素を足す提案だけで終わらず、削除案・統合案も比較。

- `SYSTEM_PROPOSALS.md`: 3案以上、資源/スキル/報酬/敵/行動経済を通した具体設計
