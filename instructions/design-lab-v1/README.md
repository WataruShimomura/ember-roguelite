# EMBER Design Lab v1: Codex向け指示セット

## 目的
Ver.0.3の単調さを、ゲームデザインの仮説→自動プレイ→実操作確認→比較→改善提案の短いサイクルで検証する。**Ver.0.4の機能を決め打ちしない**。目的はデザインの問題を見つけ、採否を判断するための根拠を作ること。

対象実装: `feature/v0.3-growth-tp` のコミット `c21c5bc4d42ff83602d2f74bd4d5f18c1678eed5`。
指示用: `instructions/design-lab-v1`。実験用: `experiment/design-lab-v1`（開始時点は上記コミットと同一）。
2026-11-18時点で `main` はVer.0.1なので実験のベースにしない。既存PRを勝手にマージしない。

## 読む順序
1. [GAME_DESIGN_PRINCIPLES.md](GAME_DESIGN_PRINCIPLES.md): 変えてよいこと・維持する設計原則
2. [CODEX_TASK.md](CODEX_TASK.md): 実験の実行手順、停止条件、成果物
3. [EXPERIMENT_PROTOCOL.md](EXPERIMENT_PROTOCOL.md): 比較設計、メトリクス、プレイ方針と評価
4. 現行 `AGENTS.md`、`docs/v0.3/`、`docs/v0.2/` とソースコード

## 実施区分
- Codexは実験ブランチのコードやデータを変更してよい。**採用候補としての実験**であり完成版ではない。
- 各実験前後のコミットを残す。比較のため以前の状態に戻せること。
- 結果報告に「採用推奨」「保留」「却下」をつける。正式なゲーム仕様採用はユーザーとのレビュー後。
- 実験ブランチへの変更・Pushと、指示ブランチへの変更は混同しない。
- Godot MCPの利用可否は実際に確認し、使用できない場合はスクリプト実行に切り替えた旨を明記。

## 完了条件
現行版のベースライン、異なる設計仮説の比較、悪用ケース（遅延等）の検査、実画面の操作確認、改善候補と副作用の報告、再実行手順。勝率だけの調整では完成と扱わない。
