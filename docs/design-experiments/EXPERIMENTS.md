## 1. TP — 開始補充を残し、自然回復プールを外す

**採用推奨。** `f7956dd` → `b3fa30c`。対照 `baseline` / 候補 `tp`。各140ラン・40盾兵プローブ・20長期戦。

| 指標 | 現行 | 開始補充のみ |
|---|---:|---:|
| 満タン率 / TPゼロ率 | 84.0% / 0.0% | 42.7% / 2.0% |
| 通常攻撃率 | 34.8% | 38.0% |
| 開始TP実補充 / 自然TP実補充 | 1,555 / 2,352 | 2,169 / 0 |
| 平均終了TP / HP | 13.68 / 195.61 | 6.67 / 195.34 |
| 総ラウンド / 総被害 | 1,762 / 15,640 | 1,795 / 15,737 |
| クリア | 140 / 140 | 140 / 140 |

- **反例。** シード42、TP0で盾兵1体、アイテムありの隔離試験では、現行の速い決着（R2、終了TP計4、自然TP3）に対して、遅延はR4、TP計10、自然TP8。代償は治療薬2と霊薬1、総被害7→14。プールなしの対はR2・TP1とR3・TP4。後者の差は有限の霊薬と与ダメージ由来で、自然回復は両方0。アイテムなしでは現行でもR2で決着し、遅延できなかった。全枠を使い切れる局面や無条件の長期利益は観測していない。
- **残る遅延。** 全ランの遅延方針は条件評価より平均3.15ラウンド長く、平均終了TP+1.05・HP−0.35。20対中17対で終了TPが多い。技能消費を抑える入力や有限アイテムの価値は残る。自然TP供給と遅延そのものを区別する。
- **副作用。** ボスHPだけ2倍、アイテム・成長なしの長期戦は両条件20/20勝。平均R8.15→9.20、TP0手番は10/473→134/524。意図的な支払いの判断が増える一方、長期戦での枯渇に注意。敵HPを変えた負荷試験なので通常ボスの成績と分けた。
- **次の手触り確認。** シード42の継戦構成で終盤まで進み、回復TPを残したときと攻撃に使ったときの選択肢を比べる。自然プール残量を追う表示を外した。 [試作コード](../../lab/design_lab_variants.gd) · [TP画面](screenshots/tp.png)

## 2. スキル — 構え貫通と確定火傷

**保留。** `b3fa30c` → `990598d`。対照 `tp` / 候補 `skills`、各140ラン。猛撃を威力−2の「鎧割り」にし、敵の構えだけを貫通する。火球を威力−4で生存対象に確定火傷を入れる「火種」に変更。コストと成長IDは共通。

| 指標 | TP対照 | 鎧割り＋火種 |
|---|---:|---:|
| 猛撃系の使用 / 構え中の敵への使用 | 561 / 4 | 163 / 45 |
| 火球系の使用 / 火傷中の敵への使用 | 543 / 146 | 185 / 41 |
| 通常攻撃率 | 38.0% | 53.2% |
| 総ラウンド / 総被害 | 1,795 / 15,737 | 2,033 / 19,494 |
| 平均終了TP / HP | 6.67 / 195.34 | 9.68 / 188.08 |
| クリア | 140 / 140 | 140 / 140 |

- **同じ局面の分岐。** シード42・継戦・強敵戦R3、構え中の盾兵HP20。通常攻撃は即時7、鎧割りは13。同ラウンド終了までのロールアウトでは、通常攻撃は敵1体を残して味方TP計10、鎧割りは撃破し戦闘終了でTP計8。味方残HPは双方187。一方、同シードの第1戦R3では盾兵HP6に双方6で撃破、通常攻撃はTP2を節約する。
- **失敗と副作用。** 構えのないボスでは鎧割りの条件が成立しない。シード42・速攻・条件評価のボスはR4→R6、治療薬消費0→2。火傷の残り時間を見る選択が生まれる一方、即時撃破を失う費用が大きい。集計は2技を同時に変更しているため、どちらが全体の長期化をどの程度引き起こしたかは未分離。構え貫通の計算根拠と火傷確率は表示し、実ダメージと状態付与をルールテストで照合した。
- **次の手触り確認。** 盾兵がいる編成といない編成で鎧割りの枠が魅力的か確認する。火種は単独のA/Bで、火傷付与、即時撃破、既存の爆ぜる残り火との相性を比べる。 [効果定義](../../lab/skills.json) · [火種の予測画面](screenshots/skills.png)

## 3. 装備 — 数値補正の指輪と、護符を与える指輪

**現行の護符案は却下。** `990598d` → `1647902`。第1サイクルのTP案とVer.0.3の攻撃スキルを共通にした。`gear` は通常の抽選、`gear_ring` / `gear_ward` / `gear_bench` / `gear_rest` は固定提示の対照。初回の装備報酬候補を同じIDの指輪に揃え、第3戦からの装着を比較。護符は味方1人に構え、本人TP1と1手番を使う。各群140ラン。

| 条件 | 第3・4戦の総R | 第3・4戦の被害 | 護符使用 / 直接防いだHP | クリア |
|---|---:|---:|---:|---:|
| POWER+3指輪を装着 | 1,074 | 14,343 | 0 / 0 | 140 |
| 護符指輪を装着 | 1,141 | 15,055 | 110 / 271 | 139 |
| 護符指輪を取得、未装着 | 1,086 | 14,164 | 0 / 0 | 140 |
| 初回に小休息を選択 | 1,087 | 14,125 | 0 / 0 | 140 |

- **変わった操作。** 護符110回の内訳は遅延33回・ランダム77回。剣士55／僧侶33／魔術師22回。予告から被害軽減を見込めた選択は28回。実測271 HPは、護符が有効な被弾時に、同じ攻撃・同じ被弾前HPで構え倍率だけを外した差分。通常報酬抽選の試行では護符10回・軽減7 HPに留まった。
- **同じ局面の反例。** シード42・速攻・強敵戦R1、敵2体が剣士を予告。本人への護符は同ラウンドの味方被害11、与ダメージ49。牽制は被害10、与ダメージ71、双方の終了TP計12。味方を守る用途も、対象の手番が敵より先なら構えが解除される。防御方針が護符を使わなかった点と、ランダムのシード50・速攻がボスで全滅した点を記録した。
- **副作用と次の確認。** 報酬を取る時点の小休息、装備枠、行動時の攻撃や牽制と競合する。固定群の取得率は実験条件なので人気の推定に使わない。人手では、遅く行動する味方に致死予告が出たときに保護のタイミングを読めるか、選べることに報酬一枠分の価値があるかを確認する。 [効果定義](../../lab/gear.json) · [報酬装着後の護符画面](screenshots/gear.png)

## 実行手順と検証範囲

PowerShellでプロジェクト直下から実行。通常起動は `Play.cmd`。エンジンのパスは環境に合わせて変更する。

```powershell
$godot = ".\tools\Godot_v4.6-stable_win64_console.exe"
& $godot --path . -- --lab=tp
& $godot --path . -- --lab=skills
& $godot --path . -- --lab=gear

.\Test.ps1 -Render
foreach ($mode in 'baseline','tp','skills','gear','gear_ring','gear_ward','gear_bench','gear_rest') {
    $log = Join-Path $PWD "tests/artifacts/lab_$mode.log"
    & $godot --headless --path . --log-file $log --script tests/design_lab.gd -- $mode
    if ($LASTEXITCODE -ne 0 -or (Select-String -LiteralPath $log -Pattern 'SCRIPT ERROR|FAIL:' -Quiet)) {
        throw "$mode failed"
    }
}
python tests/summarize_design_lab.py
foreach ($mode in 'tp','skills','gear') {
    & $godot --path . --script tests/smoke_ui.gd -- "--lab=$mode"
    if ($LASTEXITCODE -ne 0) { throw "$mode UI failed" }
}
```

- **自動プレイ。** 計1,120ラン、盾兵の遅延試験320件、長期戦160件。資源ログのHP/TP収支、自然回復の有限性、合法コマンドの受理、試作の予測と実行を照合。ランの上限700ステップ、盾兵90手、長期戦180手の超過は0件。
- **同局面。** シード42・条件評価の剣士と魔術師の手番から314スナップショット。状態と戦闘用乱数位置を複製し、アイテム以外の合法手から次ラウンド開始時点または勝敗確定まで進めた。以降の入力は条件評価。同じ戦闘内の分岐なので、予測値・被害・撃破・残TPを個別に読む。全状態は `tests/artifacts/design_lab_*.json`、抽出例とラン別指標は [METRICS.json](METRICS.json)。
- **描画と操作。** Godot MCPの該当機能は利用可能なツール一覧に見つからなかった。Godotの通常描画で既存の操作シナリオを実行し、TP35、スキル35、装備39検証が通過。装備では報酬→第3枠に装着→キー5→味方選択の予測→実行まで確認した。描画テスト用に指輪が提示される条件を固定。通常モードの描画回帰37件を含む計727件も通過した。ゲームの手触りの評価は人手で行う。
