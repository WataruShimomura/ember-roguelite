# Phase B — Godot比較結果

試作は通常ゲームから分離した。 [一括計画シーン](../../design_lab_v2/plan.tscn) · [タイムラインシーン](../../design_lab_v2/clock.tscn) · [試作の効果定義](../../design_lab_v2/content.json)

- **一括計画**は味方の行動を並べ、共有補給点の範囲で一括確定する。刻印→追撃を順番で成立させる、破勢で大技を止める、庇護で別の味方へ被害を移す選択がある。試作中に補給0の術師が刻印しか使えないと分かり、無料で攻撃予告を5弱める「減衰」を4枠目に追加した。戦闘間のHPと補給が続く。
- **タイムライン**は早く動ける味方を1人ずつ選び、技の硬直で次の時刻を変える。例えば硬直2の追撃を選ぶと印を残したまま時刻3の大技前に剣士が再行動できる。印を払う破勢なら発動を3→5へ動かし、術師の再手番を確保する。印0でも硬直違いの攻撃、刻印、拡散、庇護、反撃を使える。燃焼は対象行動前に進むため、敵を遅らせると燃焼の実ダメージも遅れる。
- **検証用の2戦**は味方HP66・54・78、同じ盾兵と詠唱士。シードで敵HPを±3、次戦では各敵HPを+16、攻撃予告を+3〜4。初戦勝利後に「追加装備なし」「返し槍」（槍撃と交換）「治療具」（庇護と交換）。治療は1手と補給4／衛士の印1を消費し最大14。自動回復を挟まず現在HPと資源を持ち越す。

## 自動プレイと報酬

シード42〜51、速攻・継戦・温存・遅延・状況判断、報酬3条件、2方式で300ミニラン・600戦。全条件が初戦を通過した。表は次戦の集計。終了HPは全滅0も含む。資源単位、ラウンドと刻、確定回数は方式ごとに異なる。

| 方式 / 次戦報酬 | 勝利 / 50 | 平均終了HP | 平均残資源 | 平均入力回数 | 反撃ダメージ計 / 味方回復計 |
|---|---:|---:|---:|---:|---:|
| 一括 / 指定なし | 40 | 24.56 | 9.38点 | 7.38 | 450 / 0 |
| 一括 / 返し槍 | 20 | 4.56 | 8.72点 | 8.64 | 1,269 / 0 |
| 一括 / 治療具 | 34 | 33.54 | 6.04点 | 7.86 | 594 / 1,148 |
| 時系列 / 指定なし | 50 | 91.00 | 5.02印 | 18.60 | 450 / 0 |
| 時系列 / 返し槍 | 50 | 84.00 | 5.48印 | 20.26 | 720 / 0 |
| 時系列 / 治療具 | 50 | 93.48 | 3.68印 | 18.24 | 180 / 1,120 |

- **一括で変わった行動。** 装備なしの次戦で刻印228・追撃222回。連携を組む価値が生まれた一方、隊の順序が固定化しやすい。継戦は平均終了HP43.8、温存は25.2で補給14.9を残した。被害を取るか資源を取るかで結果が分かれたが、温存側は余剰になりうる。装備なしでも庇護93回、反撃の構え76回。返し槍は323回使われ、予告対象の選び方は変わった。確定打点の槍撃を失い、衛士に被害が集中し、半分以上が敗北した。治療具はHPを多く残したが、温存方針の次戦勝利は10→4で、予算と庇護を失う負担があった。
- **時系列で変わった行動。** 装備なしの次戦は強襲242、拡散170、反撃の構え139、庇護50、破勢33回。状況判断は印計5.4を残し、敗北もなかった。無料技の硬直差と防御は機能するが、希少な印は使う理由が弱い。返し槍40回に加えて反撃待ちが139→296回、平均終了HP91→84。治療具は80回使われ、回復に印を使う理由を作った。軽減と回復の価値は検証できたが、報酬の自発的な選好は測っていない。
- **枯渇。** 装備・方針により偏りがある。治療具の次戦で資源0の入力は一括83回、時系列143回。後者は操作中の人物の印を参照。全員に2種類以上の無料技があり、予告にぶつける減衰・庇護・反撃や刻印連携が残る。役に立つ条件は敵の予定と対象に依存する。例えば返し槍装備の衛士が敵の構え・自己回復の予告に直面すると自分から打点を出せない。
- **遅延。** 瀕死HP5・構え中の盾兵に対し、すぐ撃破と合法手で遅らせた場合を比較。一括は3入力と1入力で、遅延側は終了HP191対198・補給18対21。時系列は3入力t2と1入力t0で、両方HP198・印6。通常走行で装備なしの遅延方針は状況判断より一括で平均4.6入力、時系列で10.5入力増。終盤の残HPと資源は両方式とも低下した。一括・返し槍では遅延方針が7/10で多く補給を残したが全10敗。未使用の残量と持ち越せる利益を区別した。各敵の撃破報酬と一度限りの自己回復を照合し、回復や待機からの供給は発生しなかった。

## 実行と検証

プロジェクト直下のPowerShellで実行する。Godotは `4.6.stable.official.89cea1439`、集計はPython 3.10以上。

```powershell
$godot = ".\tools\Godot_v4.6-stable_win64_console.exe"
& $godot --path . res://design_lab_v2/plan.tscn
& $godot --path . res://design_lab_v2/clock.tscn

$log = Join-Path $PWD "tests/artifacts/design_lab_v2.log"
& $godot --headless --path . --log-file $log --script design_lab_v2/evaluate.gd
if ($LASTEXITCODE -ne 0 -or (Select-String -LiteralPath $log -Pattern 'SCRIPT ERROR|FAIL:' -Quiet)) {
    throw "評価に失敗"
}
python design_lab_v2/summarize.py

& $godot --path . --script design_lab_v2/smoke_ui.gd
.\Test.ps1 -Render
```

- **自動評価。** 300ラン・6開始状態からの分岐・瀕死敵の対照試験。計2,299検証、失敗0。資源収支、空の資源での合法手、構えと刻印、敵回復、反撃、割込みの再適用、戦闘不能、予測の純粋性、予測と実行の一致を検査。生ログは `tests/artifacts/design_lab_v2.json`。 [集計とシード42の入力例](metrics.json)
- **操作確認。** 利用可能なツール一覧にGodot MCPは見つからなかった。Godot描画付きのボタン操作で両方式を確認。下書きの取消、事前予測、画面内の確定ボタン、古いボタンの二重実行拒否、報酬から第2戦の結果まで20件通過。Ver.0.3の既存描画回帰は戦闘549・成長67・比較74・UI37、計727件通過。サンドボックス内の試作実行にOS証明書ストアの警告が出た。対戦と画像出力は完了した。 [返し槍装着後の一括計画](screenshots/plan-reward.png) · [時系列の実行前予測](screenshots/clock-preview.png)
- **限界。** 一括は部分プラン上位6件のビーム探索で、複数手を同時に探索する。時系列は次の入力までの短い探索に硬直の重みを足す。方針間でHP・持越資源・撃破の重みを変えたが、全探索や最適攻略ではない。2方式の勝率差は共通の敵編成を別の行動経済で動かした結果であり、直接の優劣判定には使わない。判断に要する実時間、1〜2時間の周回、報酬の好み、連続した行動の体感は未検証。
