# UIと操作検証

出撃準備 → 戦闘 → 結果 → レベル確認 → 報酬 → 出撃準備。結果は戦闘の被害・回復・残HP/TPを表示する。レベル確認で各人の現在HP・最大HP・威力の前後を出し、報酬画面で個別の取得を確定する。入手直後は所持・習得だけを更新し、出撃準備で外す効果と加える効果を見て別に確定する。 [結果](screenshots/1280x720-result.png) · [レベル](screenshots/1280x720-level.png) · [報酬](screenshots/1600x900-reward.png) · [変更比較](screenshots/1600x900-exchange.png)

準備ではキャラクター別に現在の4枠、6候補の持込・控え・未習得、所持と着用を表示。候補一覧は各技のTPと説明を開ける。報酬の種類は文字で表示し、装備は現在の枠と競合を示す。傷薬は所持数とHP増加見込を出し、対象ボタンで戦間に使用する。 [準備](screenshots/1600x900-preparation.png)

戦闘は左に味方、右に敵、下に技一覧と固定詳細。Tabまたはマウスで技名・対象・基礎威力と補正・装備を参照する。技選択後に対象を指定し、予測を見て別ボタンで実行する。F1で挑発を選ぶと詠唱士の攻撃が魔術師から剣士へ移る。F3では「火傷2回→0、打点+12」を予測と実行ログの両方で照合した。TP不足・在庫なし・満タンで対象なしのコマンドは色を落とし、理由を横に表示する。条件付き追加効果がない攻撃は通常効果で実行でき、不発理由を予測欄に表示する。 [予告](screenshots/1280x720-forecast.png) · [火傷の予測](screenshots/1280x720-burn.png) · [同画面の1600×900](screenshots/1600x900-burn.png)

## 描画で確認したこと

- 両解像度でウィンドウを指定して起動し、各キャプチャの実寸と確定ボタンの表示範囲を照合した。初回の1280×720ではゲームの描画結果が1080×720だったため、v2シーンのアスペクトを広がる設定に変更した。
- 画面上のボタンや選択欄を操作し、Tab・Enter・フォーカス・マウスによる詳細参照、古いボタンの二重入力拒否、予測で状態を変えないことを確認。3戦とも同じ画面遷移を通って結果を出した。 [ボス](screenshots/1280x720-boss.png) · [冒険結果](screenshots/1600x900-final.png)
- 今回観察したのはスクリプトによる操作と画像。日本語の理解、技の説明量、複数予告が重なる初見の認知負荷、入力の迷いは人手で確認する。下部が長くなる敵3体戦ではスクロールが利用できる。 [検証ログ](TEST_REPORT.md)
