## TP/成長の検証範囲

- 開始補充の一度だけの受理、上限、KO停止、独立した自然プール。
- R1回復なし、R2回復、実回復分のみ消費、満タンで温存、同じRの再入拒否。
- 100Rの待機でも自然回復総量4を超えない。プレビュー/R1再描画で状態・乱数不変。
- 終了時破棄、RunStateへのプール非持越、次戦での再作成。
- 回復速度2/容量3で2→1の部分回復。吸収→有限アイテム→次R上限の順序。
- Lv2必須選択と二重取得防止、延焼の生存別対象・発生源、火傷消費/追加ダメージ/予測一致。
- 構えの反撃と装備反撃の併用、初回TPを1回だけ付与、初回追撃の権利消費。
- 攻撃者が反撃で死亡した場合も権利を消費し、復活後に再取得しないこと。
- Lv3の空枠、装備自動付与なし、Lv2では第3枠不可、未所有装備/第4枠拒否、所有数保存。
- Lv4の3候補、慎重な進軍の+1と発生源、戦闘ごとの有限権利初期化、新ランでLv1/2枠/成長なし。
- 3成長ルートでクリアし、同じシードと選択列で全ログ再現。既存の固定順・予告・入力revision・low-water・有限アイテム・敗北・再挑戦・集計は549回帰検証を維持。

## 途中の失敗・修正

追加の所有装備テストで、Lv3直後はまだ祭壇フェーズのため装備変更できないことを検出しました。イベントを完了して装備準備へ進む正しいテスト順に修正し、最終実行で成功しています。KO後の初回権利消費を落とす可能性はレビュー時に修正し、そのケースを追加検証しました。初期の制限環境に出た証明書ストア警告は、最終の通常権限アクセス環境では出ていません。

## 手動プレイ手順・未検証

1. Play.cmdまたはGodot F5で起動。左が味方、右が敵。HP/TPゲージと「自然 残4」を確認。
2. 1〜3、←→、D、Enterで行動。消費したTPがR2開始で戻り、その分だけ残プールが減ることを確認。
3. 通常報酬の後でLv2を選択。延焼は別敵が生存している場面、爆ぜる残り火は既存火傷、牽制強化は予告で攻撃される場面を試す。
4. 第2戦報酬後のLv3を確定し、祭壇の後で獲得済み装備を3枠目へ装着。
5. 強敵後にLv4を選びボスへ。初回条件や開始補充を内訳と全ログで確認。
6. 変化強調をOFFにして即時操作が維持されることを確認。結果のTP/HP、成長履歴を振り返りJSON保存。
7. 再挑戦でLv1/2枠に戻ること、回復しない方針で全滅した場合の結果・再挑戦も確認。

人手の長時間プレイ、全シード・全成長/装備組合せ、狭いウィンドウ、独立エクスポート、Windows以外、差替素材は未検証です。標準1280×854でHUDを確認しました。アイテム展開や多数の効果では縦スクロール/計算内訳を使用します。TPプールが空なら通常攻撃のみになる可能性は残ります。
